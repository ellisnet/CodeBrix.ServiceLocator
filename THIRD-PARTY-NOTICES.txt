CodeBrix.ServiceLocator is a shared abstraction over IoC containers and service
locators. It is a faithful port of the CommonServiceLocator library (version
2.0.7) into the CodeBrix.ServiceLocation namespace, intended as a drop-in
replacement for the CommonServiceLocator NuGet package.

CodeBrix.ServiceLocator DOES incorporate third-party source code: its types are
ported from CommonServiceLocator, which is distributed under the Microsoft
Public License (MS-PL). MS-PL is the same license this project is distributed
under (see the LICENSE file at the repository root), so the licenses are
compatible. The upstream copyright/attribution notice and the full MS-PL license

Scope of incorporation:
  The CommonServiceLocator 2.0.7 production source was ported into this
  repository under src/CodeBrix.ServiceLocator/. The ported types are:
    - IServiceLocator          (the service-location abstraction)
    - ServiceLocator           (the static ambient-container accessor)
    - ServiceLocatorImplBase   (the abstract default IServiceLocator base)
    - ServiceLocatorProvider   (the ambient-container provider delegate)
    - ActivationException      (the resolution-failure exception)

Modifications made during the port (per CodeBrix family conventions):
  - Namespace rename: the upstream `CommonServiceLocator` namespace became
    `CodeBrix.ServiceLocation`; each ported file's namespace line carries a
    `//was previously: CommonServiceLocator;` provenance comment. The namespace
    is kept FLAT (no sub-namespaces) so the type-for-type public surface matches
    the original, preserving drop-in compatibility. Package versions through
    1.0.242.982 used `CodeBrix.ServiceLocator` for this namespace; it was
    renamed because a namespace of that name hid the ported `ServiceLocator`
    class from consumers in other `CodeBrix.*` namespaces. Only the namespace
    changed; no ported type, member or behavior was altered.
  - Block-scoped namespaces were converted to file-scoped namespaces.
  - The library targets netstandard2.0 and net10.0 (upstream multi-targeted a
    dozen frameworks from net40 / netstandard1.0 through net7.0).
  - Strong-name signing was dropped. Upstream's src/Properties/AssemblyInfo.cs
    (carrying [assembly: CLSCompliant] / [assembly: SecurityTransparent]) and
    the package.snk strong-name key were NOT ported; this repository uses the
    CodeBrix-standard src/CodeBrix.ServiceLocator/InternalsVisibleTo.cs.
  - The net40-only shim src/net40/TypeInfo.cs was NOT ported (its modern BCL
    equivalents are intrinsic to net10).
  - The net40-only file src/Exceptions/ActivationException.Desktop.cs (the
    [Serializable] partial adding the SerializationInfo/StreamingContext
    constructor) was NOT ported. The upstream csproj compiles that file only for
    the net40 target; on net10 it is excluded, and porting it would surface the
    obsolete legacy-binary-serialization diagnostics (SYSLIB0051). The ported
    ActivationException therefore matches the modern-framework upstream build.
